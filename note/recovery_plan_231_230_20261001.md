# Recovery plan 231/230 after the block-14127 speculative-execution fork (2026-10-01)

## Evidence (read-only, 2026-10-01)
- Tip 14461 on m0..m3, m4 (sync-only) at 14138. Common block 14126 (hash fd0477c7, stateRoot 2ed02b90).
- 14127 splits 2-2: m0,m1,m4 = hash 58032cb0 / stateRoot 36084bfe ; m2,m3 (machine 230) = hash beb681a9 / stateRoot 32659a42.
  At 14461 stateRoot: m0=m1=5ec8ec39 ; m2=m3=1fd643eb. m2 and m3 agree on stateRoot at every checked height.
- Logs: m0 executed 14127 speculatively before 14126 was persisted (stale contract storage -> gasUsed 64067, no log);
  m2 executed it after 14126 persisted (gasUsed 66479, 1 log). Sequential semantics = the 230 side.
- Header defect on ALL nodes (parentHash != hash of previous block): m0 1 block, m2/m3 29 blocks (14139,14146,14157...).
  Stale `lastBlockHeader` in the speculative path; fixed by de15a090 (header refresh). stateRoot is unaffected, but the
  stored headers/hashes of these blocks are wrong and m2/m3 differ from each other in hash from 14139.
- Backup 20260929_143321 on both machines is block 10639 (epoch 9) - too old to be a useful restore point.

## Decision: source of truth = node-2 (machine 230)
Same stateRoot as node-3, executed 14127 sequentially. Its 29 header breaks are accepted (documented); all nodes get an
identical copy so the chain is consistent from here on.

## Steps (dev env, downtime allowed; each destructive step needs explicit go)
0. No downtime: push dev (consent), build ONE release binary set (build_check.sh already green), record md5 of simple_chain+metanode.
1. Pre-check: all 5 nodes same tip? (m4 lags), note each node's last commit index; nothing in-flight.
2. Pause Health Monitor on 231 (kill -STOP), stop ALL 5 services together (SIGTERM), confirm no simple_chain process.
3. Backup (move, not delete) current live execution state on every node to ~/backup_pre_recovery_20261001/ (same filesystem = instant).
   Keep each node's own Rust DAG (rust_consensus / dag) - never share it.
4. Copy node-2's `data/execution` (db/history, db/consensus/{nomt_db,smart_contract_code,smart_contract_storage,backup_device_key_storage},
   backup/, metadata.json) -> node-3 (local cp), -> 231 node-0 (rsync ~94G), then node-0 -> node-1, node-4 (local cp). sha/size check.
5. Install the same new binaries on all 5 nodes (md5 check against build output), keep unit files/keys.
6. Start ALL 5 together. Expect 2-4 min replay. Chain only advances when a tx arrives (empty blocks not produced).
7. Verify: block hash + stateRoot + stakeStatesRoot identical on m0-m4 at the tip and at 14127; send non-empty-calldata txs
   (several, incl. a contract call with logs) and re-compare; parentHash chain continuity over new blocks; no
   COMMITTER-CONFLICT / fork_guard / "state root mismatch" in logs. Resume Health Monitor.
8. Rollback: stop all, move backups back, start all (old binaries are in the 20260929 backup).

## Risks
- DAG vs copied Go state: each DAG may hold a different last commit index than node-2's Go state -> commit-hole class
  (see power-loss note). Mitigation: stop all together, compare indexes in step 1, watch node logs for "only syncing"; if a node
  holds, restore that node's DAG from node-2's.
- 230's stateRoot is "correct by sequential-execution evidence", not by independent replay. Optional verification
  (extra downtime): restore backup@10639 on one node with new binary and let it replay the DAG; compare stateRoot at 14461 to 1fd643eb.
- TPS may drop (speculative overlap removed by the wait-before-clone gate).
