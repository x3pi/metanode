## 5. Đánh giá End-to-End (B vs C và Khảo sát A)

### 5.1. Dữ liệu End-to-End B vs C *(Trích từ commit 907c85fb, CHƯA chạy lại)*
Dưới đây là số liệu đo E2E burst 25.000 txs Secp256k1 (batch 1.000, 4 nodes) từ phiên trước:
- **Cấu hình B (có `commitWg.Wait()`):** $6.646,01 \pm 191,6\text{ tx/s}$ (Run 1: 6.862,57, Run 2: 6.498,75, Run 3: 6.576,70).
- **Cấu hình C (bỏ `commitWg.Wait()`):** $6.334,61 \pm 185,7\text{ tx/s}$ (Run 1: 6.527,05, Run 2: 6.156,33, Run 3: 6.320,46).
- **Phép thử Welch's t-test đối với E2E B vs C:**
  $$t = \frac{6.646,01 - 6.334,61}{\sqrt{\frac{191,6^2}{3} + \frac{185,7^2}{3}}} = \frac{311,40}{154,05} \approx 2,02 \quad (df = 4,0)$$
  Giá trị $p \approx 0,113 > 0,05$. Vì cỡ mẫu $n = 3$ rất nhỏ và $p > 0,05$, **chưa đủ căn cứ thống kê để khẳng định có sự khác biệt hiệu năng giữa B và C**. Lời gọi `commitWg.Wait()` không tạo ra suy hao đo đạc được ở cấp độ E2E.

### 5.2. Khảo sát Cấu hình A trên Workload E2E *(Kết luận: INCONCLUSIVE)*
Khi triển khai `simple_chain_A` trên cluster E2E:
1. **Thiếu Raw TCP Ingress:** Commit `ec6560ce` chưa có module raw TCP listener cho `secp_tps_blast`, dẫn đến 0 tx được tiếp nhận qua TCP.
2. **Ràng buộc BLS Account Registry:** Giao dịch Secp256k1 thông thường bị từ chối với lỗi mã 18 do thiếu khóa BLS trong trie.
=> **Kết luận E2E cho Cấu hình A:** **INCONCLUSIVE** (Không thể thực hiện so sánh E2E ngang hàng vì hai bản build không cùng điều kiện giao thức tiếp nhận giao dịch).
